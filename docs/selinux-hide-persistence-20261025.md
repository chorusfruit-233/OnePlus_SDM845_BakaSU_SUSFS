# SELinux 隐藏开关重启后关闭

原有 4.9 SELinux 补丁引入了一处状态处理回归：在开机完成后第一次打开
SELinux 隐藏，管理器显示开启并提示重启，但保存到配置的值仍然是 `0`。
重启后按配置恢复，开关就再次关闭。

## 原因

1. BakaSU 在 `on_boot_completed()` 中释放未使用的策略备份。
2. 此后打开隐藏，`ksu_selinux_hide_enable()` 返回 `-EAGAIN`，要求保存设置
   并在下一次启动、备份仍存在时启用。这是上游已有的工作方式。
3. 管理器调用内核接口后执行 `ksud feature save`；该命令保存 getter 返回值。
4. 本地补丁仅在返回值为 `0` 时更新 `ksu_selinux_hide_enabled`，漏掉
   “等待重启启用”的情况，因此 getter 返回 `0`，配置也被保存为 `0`。

## 修复

启用成功或返回 `-EAGAIN` 时均记录开启请求。`ksu_selinux_hide_running`
仍只在安装成功后置位；回调恢复失败的保护、备份资源保留和错误返回继续存在。
普通初始化硬错误不会在首次尝试时被标记成启用成功。

修复位于 `bakasu-selinux-4.9.patch`，无需修改或替换官方管理器。
内核、BakaSU 的本地适配提交和原始上游提交继续分别记录，版本不带 `dirty`。

## 验证范围

`test-selinux-cleanup.py` 提取实际 setter、getter、清理和备份释放函数，
模拟 hook 安装返回值。新增场景在修复前稳定失败于保存值应为 `1` 的断言，
修复后通过，并覆盖：

- 备份释放后的启用请求、getter 保存值及模拟下次启动的配置恢复。
- 重启前取消开启请求。
- 首次初始化硬错误及已有的部分回滚、清理失败与重试。

宿主测试不启动 Android，也不等同于真机重启验证。检测报告中暴露的策略、
日志或其他信号需要在修复后的实际开关状态下重新测试。

## 真机确认

刷入修复后的内核后，重新打开一次 SELinux 隐藏，再按管理器提示重启。
此前被保存为 `0` 的开启意图无法自动恢复。
可以在有 root 权限的终端中检查持久化值和当前值：

```sh
su -c '/data/adb/ksud feature get --config selinux_hide'
su -c '/data/adb/ksud feature get selinux_hide'
```

打开后持久化值应为 `1`；重启后管理器开关也应保持开启。实际接口行为及
检测结果仍需真机反馈，源码回归通过不代表检测报告所有项目都已解决。
